> 2026-11-16 修订。旧版计划写于 React Flow 旧线；主线已切换为 `intx-next`（infinite-canvas v0.20.0 基座 + 嫁接的 INTX domain），本版按新基座与三个参考源码重写。

## 1. 产品形态与双端边界（2026-11-17 定）

**只以桌面版交付**（Tauri，Windows 优先）。同一份 `web/` 前端既是桌面应用内嵌的页面，也是开发与自动检查的通道。

| 形态 | 地位 | 说明 |
| --- | --- | --- |
| 桌面版（Tauri） | 唯一对外产品、唯一验收口径 | 承载全部用户功能 |
| 浏览器 | 开发调试 + 自动检查通道 | `vite dev` 被 `tauri dev` 复用；`vite build` 产物被桌面内嵌；Playwright 窄屏检查跑在 Chromium。不作为发布物，不承诺用户体验 |
| Docker / Vercel / Render 部署链 | 暂留，待删 | 在 Windows 安装包真机验证通过前保留，作为唯一免安装通道；通过后整体移除 |

边界规则：

- **不加项目后端**：厂商请求由前端发出——桌面端经 Rust 侧 HTTP，浏览器端经本地代理。这是「本地优先」的产品性格，不是临时状态。
- **不做双端对等**：不为浏览器维护第二套行为。只在浏览器存在的能力（本地代理开关、手填 Agent 连接）降为开发通道使用，不再作为对外功能说明。
- **平台判断只允许出现在能力适配层**（M2.5 落地后为 `web/src/lib/runtime/`），业务代码不写 `isDesktopApp`。

## 2. 当前基线（2026-11-16，按验证方式标注）

### 已验证

| 项 | 验证方式 |
| --- | --- |
| 存储事务化、崩溃补建证据、保存屏障 | 单测 + fake IndexedDB；真实浏览器/Tauri 故障界面未验 |
| Tauri 桌面壳、启动自动连接本地 Agent | 用户真机确认（dev 窗口与 `--no-bundle` release exe） |
| 本地 Agent（opencode 单车道）、模型选择、Skill 列表 | 单测 + 浏览器/桌面实测（用户确认一轮对话） |
| 任务中心页、费用预估、生成历史回填、窄屏收口 | 本次交付：tsc/单测/构建 + 浏览器 375/768 实测 |
| 真实厂商出图（ModelScope，桌面版，未开本地代理） | 2026-11-16 用户真机：出图 1 张、台账「已完成」；Key 错误与生成中取消的三态语义正确（明细见 `pending-test`） |
| 失败节点不再引导重发 | 2026-11-16 用户真机：Key 错误节点只显示提示，无重试入口 |

### 未验证（不得写成通过）

- 浏览器 + 本地代理的出图路径：未单独对照（桌面端已验，浏览器代理路径未验）。
- 安装包（MSI / NSIS）、SmartScreen、WebView2。
- 视频链路真机；时间线/导出尚未开始。

### 已知问题

- 本环境 antd 离场动画会停在 `ant-zoom-leave`，弹窗/抽屉关闭需"关闭即卸载"模式；其他存量弹窗需逐个确认。
- 浏览器直连 ModelScope 受 CORS 限制：需本地代理，或走桌面端 Rust 侧 HTTP。
- 22 个厂商请求发起点里只有 ModelScope 的 4 处真正走 Rust；其余 18 处（image / video / audio / model-plugin 等）两端都在 WebView 里发，所以「桌面端无 CORS」目前只对 ModelScope 成立。M2.5 收口。
- 渠道级「直连上游」只对 ModelScope 生效：`buildApiUrl` 的 5 个调用方都没有把渠道 `proxyMode` 传下去。M2.5 修复。
- `exportAppConfig()` 会把 `channels[].apiKey` 与 WebDAV 密码原样明文写进导出文件。M2.5 修复。
- CI 的 `checks.yml` 只跑 45 个文件 / 666 个用例，`image.test.ts`、`channel-proxy-mode.test.ts`、`agent-permissions.test.ts` 不在门禁内。M2.5 改为全量。

## 3. 里程碑

### M1 体验与治理面（已完成）

任务中心（四态筛选/详情/诊断导出/红线提示）、生成前费用预估（渠道单价）、生成历史回填画布、窄屏收口。

### M2 真机闭环（已完成，2026-11-16 用户真机）

1. ModelScope 出图：桌面版（Rust 侧 HTTP，未开本地代理）真实出图 1 张。
2. 失败注入：Key 错误 → HTTP 401 且无任务号；生成中取消 → 保留任务号、判「需先确认」，不得引导重发。
3. 参考 OpenDirector `src/backend/models.ts` 的 `proxyMode: "system" | "direct"`，在渠道配置里增加直连/代理选择（行为参考即可，代码可借）。
4. 验收清单文档化，已由用户执行并回填到 `pending-test`。

**通过标准**：已达成。浏览器 + 本地代理的对照路径记为「未验证」，不作为 M2 前置；仅浏览器生效的实现细节由 M2.5 收口。

### M2.5 架构底座（在 M3 之前）

目标：把「双端怎么收口」一次做完，使 M3 之后每加一个网络功能只改一处、只验桌面。

1. **修两个现存缺陷**（已实现，待真机确认）
   - 渠道 `proxyMode` 未透传：`buildApiUrl` 的 5 个调用方（`audio.ts:13`、`image.ts:329`、`image.ts:994`、`video.ts:43`、`model-plugin.ts:44`）都没把渠道值传下去，导致「直连上游」只对 ModelScope 生效。
   - 配置导出含明文密钥：`config-file.ts` 的 `exportAppConfig()` 原样导出 `channels[].apiKey` 与 `webdav.password`。
2. **网络出口收口**（9–13 天，代码已完成、待真机确认：`capabilities.ts` 与 `ProviderTransport`（含 `blob()`）已落地，图片、模型列表、视频、音频、脚本插件、Prompt 源与 ModelScope 全部迁移；边界检查脚本已拦截 axios / `plugin-http` / 裸 `fetch`。剩余的是真机验证：非 ModelScope 渠道出图/出片、脚本与 Prompt 源的桌面端请求、真实断网重试）
   - 新增 `web/src/lib/runtime/capabilities.ts` 作为唯一平台判断点。
   - 把 `ModelScopeTransport` 提升为通用 `ProviderTransport`（request / stream / blob），两套实现：桌面走 `@tauri-apps/plugin-http`，浏览器走原生 fetch + `withLocalProxy`。
   - 22 个厂商请求发起点全部改走它；provider 层禁止直接使用 axios / fetch / `@tauri-apps`，由边界检查脚本拦截。
   - 收口后「桌面端无 CORS」对所有厂商成立，`proxyMode` 降为浏览器开发通道的实现细节。
3. **桌面最小能力**（4–6 天）
   - 原生另存为（代码完成，待真机确认）：`lib/runtime/save-file.ts` 统一出口，桌面走 `plugin-dialog` 保存框 + `plugin-fs` 写盘，取消与写盘失败不再报成功；浏览器保留 `file-saver` 降级。全部 8 处导出/下载已迁移。
   - Windows 未签名安装包（NSIS/MSI）构建并真机安装（未开始，需有 Windows 环境的机器）。

**通过标准**：`pnpm exec vitest run src` 全量绿并作为 CI 门禁；至少一个非 ModelScope 厂商在桌面端不开本地代理能发出请求；导出的配置文件不含任何 Key；安装包在干净 Windows 上装得上、打得开。

**顺序约束**：M2.5 完成前不启动 M3 功能；网页部署链只有在第 3 项安装包验证通过后才可删除。

### M3 复用与助手（OpenDirector 首批移植）

1. **图片预设（试点，Apache 移植）**：角色三视图、面部三视图、产品三视图、分镜、多机位。参考 `src/canvas/providerPresets.ts` 及 README「Image presets」行为；接进生图工作台。
2. **画布助手交互**：参考 `src/canvas/AssistantPanel.tsx`、`AssistantConversations.tsx`、`AssistantPickers.tsx`、`AssistantLinkInfo.tsx`（会话/引用/痕迹）；权限与付费确认按 BeefTV 行为参考（三档权限、提案→价格→确认卡）。
3. **选区 → 工作流**：把选中子图保存为可复用工作流（BeefTV 行为参考）。
4. **整链一键运行**（hero8152 思路）：选终点节点 → 上游拓扑排序 → 串行/并行执行 → 每步落台账。

**通过标准**：预设出图可用；助手不绕过三态与付费确认；一键运行失败时停在首个失败点并保留已完成产物。

### M4 产品上限（OpenDirector 重点移植）

1. **时间线编辑 + MP4 导出**（最大产品级缺口）：参考 `src/canvas/TimelineEditor.tsx`、`timeline.ts`、`timelineRender.ts`、`timelineExport.ts`、`timeline-editor.css`；mediabunny 作为 npm 依赖原样使用（MPL-2.0，不修改）。可选 JSON/FCPXML 导出。
2. **媒体加工链**：截首/尾/当前帧、音视频分离、宫格拆图、超分、调色、合并（BeefTV 行为参考，已有部分）。
3. **分镜流水线**：脚本行 → 镜头节点 → 批量生成与成本 → 成片（BeefTV 行为参考）。
4. **项目库运营**：文件夹、回收站、导入/导出、批量关联。
5. **签名与更新**：代码签名（Authenticode）与自动更新源。安装包本体已在 M2.5 完成，这里补的是分发质量。

**通过标准**：时间线能导出可播放 MP4；安装包在干净 Windows 环境装、开、用、升级。

### M5 后置（按需）

技能体系、插件市场、模板沉淀、LOD 与大画布性能——只在出现真实需求或测得瓶颈后启动。

## 4. 移植义务清单（Apache-2.0）

每移植一块 OpenDirector 代码：

1. 更新 `THIRD_PARTY_NOTICES.md`：版权行、Apache-2.0 文本位置、修改说明。
2. 在源文件头注明来源与修改（Apache §4(b)）。
3. 依赖变化登记到 CHANGELOG；MPL 依赖不修改源码。
4. 改写成 intx-next 的结构（基座风格、i18n、tokens），不原样贴 React Flow 组件。

## 5. 纪律（沿用并强化）

- 测试绿 ≠ 真机通过；没验的写「未验证」及原因。
- 桌面端是唯一验收口径；浏览器只用于开发与自动检查，不作为通过依据。
- 三态不可退化：已收单一律 `confirm`，不在失败卡片引导重发。
- 任何 Key 不写进文件；未经同意不发真实请求。
- 新增边界值（超时/重试/上限）先向用户说明并确认。
- 新增代码独立成文件；不往 `project.tsx` 巨石里塞逻辑。
- 每完成一项：更新 CHANGELOG 与 `pending-test`，用户确认后才写入 features。
